## Running Moodle

If not already logged in, log in to [rancher.cloud.e-infra.cz](https://rancher.cloud.e-infra.cz). See the [Rancher](../rancher/rancher) section for details.

This guide walks you through installing Moodle, a web-based learning platform that provides educators, administrators, and learners with a robust, secure, and integrated system for creating personalized learning environments. The application enables you to create a Moodle site under a hostname of your choice.

### Select Application to Run

Navigate through `Only User Namespaces` (1), `App & Marketplace` (2), `Charts` (3), and `cerit-sc` (4), then select `moodle` (5). Refer to the screenshot below.

![Select Moodle application from chart catalog](/img/ceritsc/apps/moodle/selectapp.png)

### Install the Application

Click on the chart, then click `Install` to continue.

![Select Moodle chart version](/img/ceritsc/apps/moodle/selectversion.png)

Select your namespace and assign a name for your Moodle application, then click `Next`.

![Select namespace and name for Moodle installation](/img/ceritsc/apps/moodle/namespace.png)

Multiple configuration options appear. We will focus on the `General` section. `Hostname` (1) is your access URL; if left empty, it defaults to moodle-namespace.dyn.cloud.e-infra.cz. `Moodle username` (2) and `Moodle password` (3) are your login credentials; fill them in as desired. `Site name` (4) is the name of your site; if left empty, it defaults to "New Site". `Moodle email` (5) is the email address for your Moodle account. `Replicas` (6) specifies the number of replicas you want.

![General configuration section for Moodle installation](/img/ceritsc/apps/moodle/gen1.png)

Next, configure your database. When the `Internal MariaDB` field is checked, the system provides a MariaDB database.

![Internal MariaDB database configuration for Moodle](/img/ceritsc/apps/moodle/mariadb.png)

To create a backup, check the `Backup` field (1). `Backup-keep` (2) specifies the number of backups to retain. `Schedule` (3) defines how frequently the database is backed up. `ClaimName` (4) is the name of the PersistentVolumeClaim for the backup.

![Backup configuration options for Moodle database](/img/ceritsc/apps/moodle/backup.png)

To use an existing external database, uncheck the `Internal MariaDB` field (1); several options will appear. `Type` (2) is a dropdown menu listing supported database types. In the `Host` field (3), enter the hostname of the existing database. The `port` field (4) follows the same pattern. The `User` (5) and `Password` (6) fields contain the database credentials. `Database` (7) is the name of the existing database.

![External database configuration for Moodle](/img/ceritsc/apps/moodle/external.png)

When satisfied with the configuration, click the `Install` button and wait a few minutes for this message to appear.

![Successful Moodle installation confirmation](/img/ceritsc/apps/moodle/success.png)

## Login to the Running Instance

Once the application is running, navigate through Service Discovery (1) and Ingresses (2). You will see a list of Ingresses. Locate the name you used earlier and click Target (4) to log in to the application. Click `Log in` and enter your username and password from the previous steps.

![Login to Moodle application through Ingress](/img/ceritsc/apps/moodle/login.png)

Your new site will appear.

![Moodle site dashboard after successful login](/img/ceritsc/apps/moodle/mod.png)

## Delete the Running Instance

To delete the application when it is no longer needed, navigate to App & Marketplace (1), Installed Apps (2), select the application (3), and click Delete (4). Data in the home directory is preserved. Running the application again with the same name restores access to the home directory folder.

![Delete Moodle application interface](/img/ceritsc/apps/moodle/del1.png)

Wait for the following message to appear.

![Moodle application deletion confirmation message](/img/ceritsc/apps/moodle/del2.png)
