Následující text popisuje, jak spustit [Nextflow](https://nextflow.io) pipeline v Kubernetes clusteru CERIT-SC.

Musíte nainstalovat Nextflow na svém místním počítači nebo na jakémkoli počítači, ze kterého spustíte Nextflow; pipeline se na tomto počítači nespustí, poběží v Kubernetes clusteru a počítač slouží pouze k jejímu spuštění. Počítač nemusí být online, zatímco pipeline stále běží.

## Instalace Nextflow

Pro instalaci Nextflow zadejte tento příkaz ve svém terminálu:

```shell
curl -s https://get.nextflow.io | bash
```
Můžete nainstalovat konkrétní verzi Nextflow exportováním proměnné prostředí `NXF_VER` před spuštěním instalačního příkazu, např.:

```shell
export NXF_VER=24.04.4
curl -s https://get.nextflow.io | bash
```

V současnosti je 24.04.4 nejvyšší dostupná verze pomocí této metody. Můžete si však také stáhnout nejnovější verzi z githubu:
`https://github.com/nextflow-io/nextflow`, kterou lze nainstalovat následujícím způsobem:

```shell
git clone https://github.com/nextflow-io/nextflow.git
cd nextflow
git checkout v24.04.4
make compile install
```

## Architektura Nextflow 

Nextflow pipeline se spouští pomocí příkazu `nextflow`, např.:

```shell
nextflow run hello
```

což spustí pipeline `hello`. Spuštění pipeline se skládá ze dvou částí:
*řídícího modulu workflow* a *pracovníků*. *Řídící modul workflow* spravuje
běh pipeline, zatímco *pracovníci* vykonávají jednotlivé úkoly. 

Nextflow engine očekává, že *řídící modul workflow* a *pracovníci* mají
přístup k nějakému sdílenému úložišti. Na místním počítači je to obvykle jen
konkrétní adresář, v případě distribuovaného výpočtu to musí být
síťové úložiště, jako je NFS mount. Uživatel musí specifikovat, jaké úložiště může být
použito při spuštění Nextflow.

## Spuštění Nextflow v Kubernetes

V případě K8s je *řídící modul workflow* spuštěn jako
[Pod](https://kubernetes.io/docs/concepts/workloads/pods/) v Kubernetes
clusteru. Jeho úkolem je spouštět *pracovní* pod podle definice pipeline.
Pod *řídícího modulu workflow* má nějaké vygenerované jméno jako `naughty-williams`.
*Pracovníci* mají hashované názvy jako `nf-81dae79db8e5e2c7a7c3ad5f6c7d59c6`.

Nejprve musíte mít:
- nainstalovaný [`kubectl`](../kubernetes/kubectl) s `kubeconfig` souborem na očekávaném místě `$HOME/.kube/config`. 
- Kubernetes [Namespace](https://kubernetes.io/docs/concepts/overview/working-with-objects/namespaces/) pro spuštění (viz [zde](../kubernetes/ns), jak zjistit svůj namespace).
- vytvořený [PVC](https://kubernetes.io/docs/concepts/storage/persistent-volumes/) (viz [zde](../kubernetes/pvc), jak to udělat).

### Konfigurace 🧩

Spuštění Nextflow pipeline v Kubernetes vyžaduje místní konfiguraci s některým nezbytným obsahem:

```js filename="nextflow.config" copy
k8s {
   namespace = '[your_namespace]'
   runAsUser = 1000
   computeResourceType = 'Job'
   storageClaimName = '[name_of_created_pvc]'
   storageMountPath = '[mountpath]'
   launchDir = '[mountpath_from_storageMountPath]/[some_launchDir_path]'
   workDir = '[mountpath_from_storageMountPath]/[some_workDir_path]'
}

executor {
  queueSize = 30
}

process {
   executor = 'k8s'
   pod = [[securityContext:[fsGroupChangePolicy:'OnRootMismatch', runAsUser:1000, runAsGroup:1, fsGroup:1]], [automountServiceAccountToken:false]]
}
```

Musíte nastavit `namespace` na správnou hodnotu (namespace, ke které máte přístup). Nastavte název PVC, které jste vytvořili, jako `storageClaimName`, bude sloužit jako sdílený pracovní prostor pro Nextflow. Nastavte `storageMountPath` na jakoukoli cestu, kde byste chtěli připojit tento PVC (doporučujeme `/mnt`). Nastavte `launchDir` a `workDir`, aby ukazovaly někam na PVC. Dbejte na to, pokud spouštíte Nextflow paralelně, vždy používejte různé `launchDir` a `workDir` pro paralelní běhy.

Existuje spousta dalších možností přizpůsobení pro pracovníky nebo jednotlivé procesy. Je možné:
- připojit další PVC nebo tajemství
- nastavit požadavky na zdroje (cpu, paměť)
- přidat štítky nebo anotace
- atd.

Pro přizpůsobení jednotlivých procesů (např. paměť, cpu) viz sekce dokumentace Nextflow o [procesech](https://www.nextflow.io/docs/latest/process.html). Pro přizpůsobení samotného podu (např. připojení pvc) viz podrobnosti v [dokumentaci podu nextflow](https://www.nextflow.io/docs/latest/process.html#pod). 

Při míchání generické konfigurace procesu 

```js
process {...}
```

a selektorů se uplatňují následující pravidla priority (od nižší k vyšší):

- Generální konfigurace procesu (`nextflow.config`).
- Specifická direktiva procesu definovaná ve skriptu workflow.
- definice selektoru withLabel.
- definice selektoru withName.

### Spuštění ⏱

Pro spuštění pipeline musíte použít podřízený příkaz `kuberun` příkazu `nextflow`. Pokud používáte verzi `nextflow` 22.06.1 nebo novější, musíte přidat možnosti 

```shell
-head-image 'cerit.io/nextflow/nextflow:24.04.4' -head-memory 4096Mi -head-cpus 1
```

Tyto možnosti jsou vyžadovány pouze pro *pod řídícího modulu workflow* v našem clusteru. `head-memory`/`head-cpus` specifikují množství paměti/cpu vyhrazené pro pod řídícího modulu -- použijte vyšší číslo, pokud se očekává, že vaše pipeline vygeneruje tisíce úkolů.

Příklad příkazu pro spuštění:

```shell
nextflow kuberun hello -head-image 'cerit.io/nextflow/nextflow:24.04.4' -head-memory 4096Mi -head-cpus 1 -v PVC:/mnt 
```

Pokud používáte verzi `nextflow` nižší než 22.06.1 nebo dostanete chybovou zprávu informující o `head-image not known`, musíte přidat možnost

```shell
-pod-image 'cerit.io/nextflow/nextflow:22.06.1' 
```

Příklad příkazu pro spuštění:

```bash
nextflow kuberun hello -pod-image 'cerit.io/nextflow/nextflow:22.06.1'
```

Konfigurační soubor může vypadat následovně:

```js filename="nextflow.config" copy
k8s {
   namespace = 'nf-ns'
   runAsUser = 1000
   computeResourceType = 'Job'
   storageClaimName = 'pvc-nf'
   storageMountPath = '/mnt'
   launchDir = '/mnt/data1'
   workDir = '/mnt/data1/tmp'
}

executor {
  queueSize = 30
}

process {
   executor = 'k8s'
   memory = '500M' // THIS WILL BE DEFAULTLY APPLIED TO ALL WORKERS IF NOT SPECIFIED IN WORKFLOW SCRIPT
   pod = [[label: 'hpctransfer', value: 'must'], [securityContext:[fsGroupChangePolicy:'OnRootMismatch', runAsUser:1000, runAsGroup:1, fsGroup:1]], [automountServiceAccountToken:false], [secret: 'keythings', mountPath: '/etc/secrets']] // THIS WILL BE APPLIED TO ALL WORKERS
   
   withLabel:VEP { // THIS WILL BE APPLIED ONLY TO PROCESS WITH LABEL VEP EVEN IF SPECIFIED IN WORKFLOW SCRIPT
       memory = {check_resource(14.GB * task.attempt)}
   }
   
}

process mdrun { // THIS WILL BE APPLIED ONLY TO PROCESS NAMED mdrun IF NOT SPECIFIED IN WORKFLOW SCRIPT
  cpus 20
}
```

### Debug 🐞 
Doporučujeme sledovat svůj namespace v GUI Rancher nebo v příkazovém řádku, když odesíláte pipeline. Ne všechny problémy se propagují do terminálu, zejména chyby související s Kubernetes, jako je překročení kvóty. Můžete otevřít záložku `Jobs` v GUI Rancher a dávat pozor na úlohy, které jsou `In progress` příliš dlouho nebo ve stavu `Error`. Užitečné příkazy mohou zahrnovat 

```shell
kubectl get jobs -n [namespace] // GET ALL JOBS IN NAMESPACE
kubectl describe job [job_name] -n [namespace] // FIND OUT MORE ABOUT JOB AND WHAT IS HAPPENING WITH IT

kubectl get pods -n [namespace] // GET ALL PODS IN NAMESPACE
kubectl describe pod [pod_name] -n [namespace] // FIND OUT MORE ABOUT POD AND WHAT IS HAPPENING WITH IT
kubectl logs [pod_name] -n [namespace] // GET POD LOGS (IF AVAILABLE)
```

Pokud úloha čeká na spuštění příliš dlouho, zkuste popsat úlohu. Může to odhalit překročení kvóty ve vašem namespace:

```
  Warning  FailedCreate  18m    job-controller  Error creating: pods "nf-5dd9dc33d33c729b5cd57c818bafba86-lk4tl" is forbidden: exceeded quota: default-kbz9v, requested: requests.cpu=8, used: requests.cpu=16, limited: requests.cpu=20
```

Pokud se vám to stane, zvažte snížení problematických požadavků na zdroje kontroleru pracovního postupu nebo procesů, které mohou vyžadovat příliš mnoho. Pokud nevíte, co dělat, <a href="mailto:k8s@ics.muni.cz">kontaktujte nás</a> a společně najdeme řešení.

## Spuštění Nextflow Hello pipeline

Stáhněte [nextflow.config](deployments/nextflow.config), který je připraven k použití, stačí změnit `namespace` na správnou hodnotu (namespace, ke kterému máte přístup) a specifikovat `launchDir` a `workDir`, aby ukazovaly někam na PVC. Dávejte pozor, pokud spouštíte Nextflow paralelně, vždy používejte různé `launchDir` a `workDir` pro paralelní běhy.

Musíte soubor uchovávat v aktuálním adresáři, kde je spuštěn příkaz `nextflow`, a musí být pojmenován `nextflow.config`.

Aby Nextflow spustil pipeline `hello` v Kubernetes, spusťte následující příkaz:

```shell
nextflow kuberun hello -pod-image 'cerit.io/nextflow/nextflow:22.06.1' -v PVC:/mnt 
```

kde PVC je název PVC, jak bylo uvedeno výše. Bude připojeno jako /mnt.
Tento bod připojení byste měli používat, protože některé pipeline očekávají tuto lokaci.

Pokud používáte verzi `nextflow` 22.06.1 nebo novější, jak bylo uvedeno výše, použijte místo toho:

```shell
nextflow kuberun hello -pod-image 'cerit.io/nextflow/nextflow:22.06.1' -head-memory 4096Mi -head-cpus 1 -v PVC:/mnt 
```

Pokud bylo vše správně, měli byste vidět výstup jako tento:

```
 Pod started: naughty-williams
 N E X T F L O W  ~  version 22.06.1-SNAPSHOT
 Launching `nextflow-io/hello` [naughty-williams] - revision: e6d9427e5b [master]
 [f0/ce818c] Submitted process > sayHello (2)
 [8a/8b278f] Submitted process > sayHello (1)
 [5f/a4395f] Submitted process > sayHello (3)
 [97/71a2e0] Submitted process > sayHello (4)
 Ciao world!
 Hola world!

```

### Upozornění

* Pokud pipeline běží dlouho (což není případ pipeline `hello`), příkaz `nextflow` končí s ukončením spojení. To je normální a neznamená to, že pipeline již neběží. Přestane pouze logovat do vašeho terminálu. Stále můžete najít protokoly kontroleru pracovního postupu v GUI Rancher.

* Běh pipeline může být ukončen z GUI Rancher, stisknutí `ctrl-c` pipeline neukončí.

* Protokol ladění pipeline lze nalézt na PVC v `launchDir/.nextflow.log`. Po sobě jdoucí běhy rotují protokoly, aby nebyly přepsány.

* Pokud pipeline selže, můžete se pokusit obnovit pipeline pomocí příkazové volby `-resume`, vytvoří nový běh, ale pokusí se přeskočit již dokončené úkoly. Viz [podrobnosti](https://www.nextflow.io/blog/2019/demystifying-nextflow-resume.html).

* Všechny běhy (úspěšné nebo selhané) udržují *pod kontroleru pracovního postupu* viditelný v GUI Rancher, selhané pracovníky jsou také uchovávány v GUI Rancher. Můžete je podle potřeby odstranit z GUI.

* U některých *pracovníků* nejsou protokoly dostupné v GUI Rancher, ale protokoly lze sledovat pomocí příkazu:

```shell
kubectl logs POD -n NAMESPACE 
```

  kde `POD` je název *pracovníka* (např. `nf-81dae79db8e5e2c7a7c3ad5f6c7d59c6`) a `NAMESPACE` je používaný namespace.

## nf-core/sarek pipeline

[nf-core/sarek](https://nf-co.re/sarek) je analytická pipeline pro detekci germinálních nebo somatických variant (předzpracování, volání variant a anotace) z WGS / cíleného sekvenování.

### Spuštění v Kubernetes

Sarek vyžaduje specifický
[nextflow.config](/examples/ceritsc/nextflow/nextflow-sarek.config),
nastavuje více paměti pro proces VEP, který je součástí pipeline. Při základních nastaveních bude proces VEP pravděpodobně zabit kvůli paměti.
Také vyžaduje specifický
[custom.config](/examples/ceritsc/nextflow/custom.config)
protože git verze Sarek obsahuje chybu, takže výstupní statistiky budou zapisovány do nesprávných souborů.

Pipeline Sarek používá funkce v konfiguraci pipeline. Nicméně,
funkce v konfiguraci pipeline momentálně nejsou podporovány executor `kuberun`. 

Abychom se vypořádali s touto chybou, potřebujete verzi Nextflow 22.06.1-edge nebo novější.

Stáhněte
[nextflow-cfg.sh](/examples/ceritsc/nextflow/nextflow-cfg.sh)
a
[nextflow.config.add](/examples/ceritsc/nextflow/nextflow.config.add)
a umístěte obě na PVC (do jeho kořenového adresáře). Nepřejmenovávejte soubory a udělejte `nextflow-cfg.sh` spustitelným (`chmod a+x nextflow-cfg.sh`).

Nyní, pokud jste připravili svá data na PVC, můžete spustit pipeline Sarek následujícím příkazem:

```shell
nextflow kuberun nf-core/sarek -head-memory 4096Mi -head-cpus 1 -head-prescript /mnt/nextflow-cfg.sh -pod-image 'cerit.io/nextflow/nextflow:22.06.1' -v PVC:/mnt --input /mnt/test.tsv --genome GRCh38 --tools HaplotypeCaller,VEP,Manta
```


kde `PVC` je zmíněný PVC a `test.tsv` obsahuje vstupní data umístěná na PVC.

### Upozornění

* Doporučuje se stáhnout *igenome* z umístění S3 Amazon na místní PVC. To rychle zrychlí možnost `-resume` v případě, že běh pipeline selže a vy ji znovu spustíte, abyste pokračovali. Také to zmírňuje přetížení Amazonu nebo problémy sítě, které vedou k selhání pipeline. Jakmile stáhnete *igenome*, jednoduše přidejte něco jako `--igenomes_base /mnt/igenome` do příkazových možností `nextflow`.

* Pokud obdržíte chybu o neznámém `check_resource`, pak jste selhali s nastavením `nextflow-cfg.sh` a `nextflow.config.add`.

* Běh pipeline končí stacktrace a chybou `No signature of method: java.lang.String.toBytes()`. To je normální a je to výsledek toho, že nebyla specifikována e-mailová adresa pro odeslání konečného e-mailu. Není třeba se obávat.

* Běh pipeline nečistí workDir, je na uživateli, aby jej vyčistil/odstranil.

* Ruční obnovení Sarek je možné pomocí různých specifikací `--input`. Viz [zde](https://nf-co.re/sarek/2.7.1/usage#troubleshooting).


## vib-singlecell-nf/vsn-pipelines pipeline

[vsn-pipelines](https://vsn-pipelines.readthedocs.io/en/latest/) obsahují více pracovních postupů pro analýzu dat z jednoho buněčného transkriptomu a závisí na řadě nástrojů.

### Kubernetes Run

Musíte stáhnout specifický pipeline [nextflow.config](/examples/ceritsc/nextflow-vsn.config) a umístit jej do aktuálního adresáře, odkud spouštíte Nextflow. Tato pipeline používá parametr `-entry` k určení vstupního bodu pracovního postupu. Pokud není vyřešena [tato otázka #2397](https://github.com/nextflow-io/nextflow/issues/2397), je potřeba opravená verze Nextflow. Abyste se vypořádali s touto chybou, potřebujete verzi Nextflow 22.06.1-edge nebo novější.

Na PVC musíte připravit data do adresářů specifikovaných v `nextflow.config`, podívejte se na všechny výskyty `/mnt/data1` v konfiguraci a změňte je podle potřeby.

Konzultujte [dokumentaci](https://vsn-pipelines.readthedocs.io/en/latest/index.html) pro další možnosti konfigurace.

Pipeline můžete spustit následujícím příkazem:

```shell
nextflow -C nextflow.config kuberun vib-singlecell-nf/vsn-pipelines -pod-image 'cerit.io/nextflow/nextflow:22.06.1' -head-cpus 1 -head-memory 4096Mi -v PVC:/mnt -entry scenic
```

kde `PVC` je zmíněný PVC, `scenic` je vstupní bod pipeline a `nextflow.config` je stažený `nextflow.config`.

### Upozornění

* Pro paralelní běh musíte nastavit `maxForks` v `nextflow.config` spolu s parametrem `params.sc.scenic.numRuns`. Konzultujte [dokumentaci](https://vsn-pipelines-examples.readthedocs.io/en/latest/PBMC10k_multiruns.html).

* Proměnná `NUMBA_CACHE_DIR`, která ukazuje na `/tmp` nebo jiný zapisovatelný adresář, je požadavek, jinak se provádění nezdaří z důvodu zamítnutí oprávnění. Snaží se aktualizovat pouze pro čtení části běžícího kontejneru.

## Použití GPU

Použití GPU v kontejnerech je jednoduché, stačí přidat:

```
  accelerator = 1
```

do sekce procesu `nextflow.config`, např.:

```js filename="nextflow.config" copy
process {
   executor = 'k8s'

   withLabel:VEP {
      accelerator = 1
   }
}
```
