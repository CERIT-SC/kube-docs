## Autentizace příchozího provozu

Pokud chcete použít základní autentizaci nebo OAuth pro příchozí provoz (Ingress), postupujte podle pokynů v [oficiální dokumentaci](https://kubernetes.github.io/ingress-nginx/examples/auth/basic/) nebo v [naší dokumentaci](./expose).

Tento přístup má významnou bezpečnostní chybu: autentizace je vyžadována pouze při připojování přes Ingress, například zvenčí Kubernetes clusteru. Uživatelé platformy se však mohou připojit také zevnitř clusteru přímo k odpovídající službě (Service) – museli by uhádnout její IP adresu. V takových případech není autentizace vyžadována.

Tuto chybu lze zmírnit pomocí [síťové politiky (Network Policy)](https://kubernetes.io/docs/concepts/services-networking/network-policies/), která omezuje zdroj síťového provozu. V tomto případě povolte příchozí provoz na server pouze z jmenného prostoru *kube-system*. Jmenný prostor *kube-system* hostuje instanci Ingress NGINX, takže jsou vyžadována pouze připojení z tohoto jmenného prostoru.

Příklad síťové politiky můžete [stáhnout zde](/examples/ceritsc/manifests/netpolicy.yaml). Tato politika povoluje příchozí provoz z *kube-system* na pod (Pod) s názvem `myapp`. Tato politika se aplikuje na *jmenný prostor*, ve kterém se nachází pod `myapp`.

## Jednotné přihlášení e-infra (BETA)

Pro zabezpečení vaší aplikace můžete použít službu jednotného přihlášení e-infra. Pro její povolení přidejte několik anotací k příchozímu provozu (Ingress).
Tento návod ukazuje, jak upravit existující příchozí provoz tak, aby obsahoval jednotné přihlášení.

Tento příklad představuje existující příchozí provoz:

```yaml title="ingress.yaml"
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ingress-name
  annotations:
    kubernetes.io/tls-acme: "true"
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - "hostname.dyn.cloud.e-infra.cz"
      secretName: hostname-dyn-cloud-e-infra-cz-tls
  rules:
  - host: "hostname.dyn.cloud.e-infra.cz"
    http:
      paths:
      - path: /
        backend:
          service:
            name: service-name
            port:
              number: port-number
        pathType: Prefix
```

Nejprve přidejte několik anotací k příchozímu provozu:

```yaml {8,9}
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ingress-name
  annotations:
    kubernetes.io/tls-acme: "true"
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
+   nginx.ingress.kubernetes.io/auth-url: "https://$host/oauth2/auth?allowed_emails=email1@ics.muni.cz, email2@ics.muni.cz, email3@ics.muni.cz"
+   nginx.ingress.kubernetes.io/auth-signin: "https://$host/oauth2/start?rd=$scheme%3A%2F%2F$host$escaped_request_uri"
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - "hostname.dyn.cloud.e-infra.cz"
      secretName: hostname-dyn-cloud-e-infra-cz-tls
  rules:
  - host: "hostname.dyn.cloud.e-infra.cz"
    http:
      paths:
      - path: /
        backend:
          service:
            name: service-name
            port:
              number: service-port-number
        pathType: Prefix
```

Anotace `nginx.ingress.kubernetes.io/auth-url` obsahuje řetězec dotazu, který určuje seznam uživatelů, kteří mají přístup na webovou stránku. Změňte pouze seznam e-mailů v tomto poli; adresu URL nijak neměňte.

Druhá anotace říká příchozímu provozu, aby po ověření uživatele přesměroval zpět na webovou stránku.

Nyní, když je příchozí provoz nakonfigurován tak, aby používal koncový bod jednotného přihlášení, nakonfigurujte samotný koncový bod jednotného přihlášení aplikací následujícího YAML souboru:

```yaml copy
apiVersion: v1
kind: Service
metadata:
  name: ingress-name-oauth
spec:
  type: ExternalName
  externalName: oauth2-proxy.kube-system.svc.cluster.local
  ports:
  - name: http
    port: 4180
    protocol: TCP

---

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ingress-name-oauth
  annotations:
    kubernetes.io/tls-acme: "true"
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
spec:
  kubernetes.io/ingress.class: "nginx"
  tls:
    - hosts:
        - "hostname.dyn.cloud.e-infra.cz"
      secretName: hostname-dyn-cloud-e-infra-cz-tls
  rules:
  - host: "hostname.dyn.cloud.e-infra.cz"
    http:
      paths:
      - path: /oauth2
        backend:
          service:
            name: ingress-name-oauth
            port:
              number: 4180
        pathType: Prefix
```

Všimněte si, že hodnoty `hosts` a `secretName` odpovídají hodnotám v původním příchozím provozu.
Nahraďte všechny výskyty `ingress-name` a `hostname` názvem vašeho příchozího provozu a adresou URL vaší webové stránky, poté soubor aplikujte.

Po provedení všech změn je vaše webová stránka nyní zabezpečena službou jednotného přihlášení e-infra.
