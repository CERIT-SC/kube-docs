title: Vystavování aplikací
---

Tato kapitola vysvětluje, jak nakonfigurovat externí přístup k vaší aplikaci z externí sítě (neboli "z venku"). I když je možné k aplikaci přistupovat přímo přes IP adresu, tento přístup se nedoporučuje. Místo toho následujte pokyny níže pro správné vystavení aplikace.

Existují dva hlavní typy aplikací, které lze vystavit: **webové aplikace** a **ostatní aplikace**. Hlavní rozdíl mezi těmito typy spočívá v požadavcích na IP adresy. Webové aplikace sdílejí IP adresu s ostatními webovými aplikacemi, zatímco ostatní aplikace vyžadují vyhrazenou IP adresu pro každou službu. Vzhledem k omezenému počtu dostupných IP adres se upřednostňuje webový přístup, kdykoli je to možné.

V této dokumentaci jsou poskytovány fragmenty YAML. Tyto definice YAML by měly být nasazeny pomocí `kubectl`, například takto:

```shell
kubectl create -f file.yaml -n namespace
```

kde `file.yaml` obsahuje definice YAML a `namespace` je Namespace, ve kterém aplikace běží.

<Callout title="Předpoklad" icon="✅">
Tento návod předpokládá, že vaše aplikace (`Deployment`) je již nasazena. Pokud si nejste jisti, podívejte se na příklad [Hello World](../examples/helloworld).
</Callout>

## Webové aplikace

Webové aplikace komunikují pomocí protokolu `HTTP` a jsou vystavovány pomocí prostředků `Ingress`.

### Přehled

Celková architektura je znázorněna na následujícím obrázku:

![Networking](/img/ceritsc/expose-overview.svg)

Pro vystavení webové aplikace potřebujete:

1. `Service`, který naváže port na vaši aplikaci.
2. Prostředek `Ingress`, který vystaví `Service` na internet.

Předpokládejme, že máme aplikaci běžící na portu `8080`. Nejprve definujeme `Service`:

```yaml title="service.yaml"
apiVersion: v1
kind: Service
metadata:
  name: application-svc
spec:
  type: ClusterIP
  ports:
  - name: application-port
    port: 80
    targetPort: 8080
  selector:
    app: application
```

V této konfiguraci:

- `selector: app: application` musí odpovídat popisku aplikace v `Deployment`.
- Hodnoty `application-svc` a `application-port` jsou libovolné názvy.

Po vytvoření Service definujeme Ingress:

```yaml title="ingress.yaml"
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: application-ingress
  annotations:
    kubernetes.io/tls-acme: "true"
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - "application.dyn.cloud.e-infra.cz"
      secretName: application-dyn-cloud-e-infra-cz-tls
  rules:
  - host: "application.dyn.cloud.e-infra.cz"
    http:
      paths:
      - backend:
          service:
            name: application-svc
            port:
              number: 80
        pathType: ImplementationSpecific
```

Zde:

- `service.name: application-svc` musí odpovídat názvu metadat `Service`.
- `Ingress` vystavuje aplikaci na URL `application.dyn.cloud.e-infra.cz`, které slouží jako přístupný koncový bod (funguje jako "IP" pro dosažení vaší aplikace).
- Pokud je doména v rámci `dyn.cloud.e-infra.cz`, bude automaticky zaregistrována.
- Sekce `tls` umožňuje automatickou správu certifikátů přes Let's Encrypt.

<Callout title="Poznámka" icon="📌">
Pokud je zahrnuta sekce tls, dochází k ukončení TLS na NGINX Ingress. Vaše aplikace by měla obsluhovat provoz přes HTTP, zatímco externí komunikace je zabezpečena přes HTTPS.
</Callout>

### Důležité aspekty

❗ **Varování o bezpečnosti:**

TLS je **ukončeno na hranici clusteru** při použití `NGINX Ingress`. Komunikace uvnitř clusteru, zejména v rámci jednoho uzlu, zůstává nešifrovaná. Pokud je vyžadováno úplné end-to-end šifrování, měli byste:

- Vynechat sekce tls a annotations.
- Poskytnout certifikát a klíč přímo ve vašem Podu.

❗ **Zacházení se smíšenými konfiguracemi HTTP/HTTPS:**

Některé aplikace mohou být zmateny, když jsou nakonfigurovány na použití `HTTP` interně, ale vystaveny jako `HTTPS`. Pokud vaše aplikace generuje absolutní URL, ujistěte se, že používají `HTTPS`.

- `Ingress` nastavuje hlavičku `HTTP_X_SCHEME` na `HTTPS`, když je TLS ukončeno.
- Mnoho aplikací však očekává `X_FORWARDED_PROTO` (což Kubernetes `NGINX` nenastavuje).
  Například v Django byste měli nastavit:

  ```python
  SECURE_PROXY_SSL_HEADER = ("HTTP_X_SCHEME", "https")
  ```

Pokud vaše aplikace vyžaduje HTTPS end-to-end, viz sekce HTTPS Target níže.

### Vlastní doménové jméno (FQDN)

Je možné použít vlastní doménové jméno místo `*.dyn.cloud.e-infra.cz`.

1. Nastavte `CNAME` DNS záznam.

   - Pro `kuba-cluster` nastavte cíl `CNAME` na `kuba-pub.cerit-sc.cz`.
   - Pro `kubh-cluster` nastavte cíl `CNAME` na `kubh-pub.cerit-sc.cz`.

2. Definujte `Ingress` s vlastní doménou:

   ```yaml title="ingress.yaml"
   apiVersion: networking.k8s.io/v1
   kind: Ingress
   metadata:
     name: application-ingress
     annotations:
       kubernetes.io/tls-acme: "true"
       cert-manager.io/cluster-issuer: "letsencrypt-prod"
   spec:
     ingressClassName: nginx
     tls:
       - hosts:
           - "my-name"
         secretName: my-name-tls
     rules:
     - host: "my-name"
       http:
         paths:
         - backend:
             service:
               name: application-svc
               port:
                 number: 80
           pathType: ImplementationSpecific
   ```

#### Poznámka

`CNAME` musí být předem nastaven a propagován, aby služba Let's Encrypt mohla ověřit doménu při vyžádání TLS. To znamená, že bezproblémová migrace z jiných systémů na naši infrastrukturu není snadno možná.

### Autentizace

`Ingress` může vyžadovat autentizaci uživatele, aby poskytl omezený přístup k `Service`. Autentizaci lze nastavit pomocí `Secret` a anotací.

Nejprve nastavte tajemství:

```yaml title="secret.yaml"
apiVersion: v1
kind: Secret
metadata:
  name: secretref
type: Opaque
data:
   auth: password
```

Kde `secretref` je libovolný název a heslo je `base64` kódované `htpasswd`. Heslo lze vygenerovat tímto příkazem: `htpasswd -n username | base64 -w0`, kde `username` je požadované uživatelské jméno pro přihlášení. Vrátí text jako `Zm9vOiRhcHIxJGhOZVRzdngvJEkyVk9NbEhHZDE1N1gvYTN2aktYSDEKCg==`, který bude použit místo `password` v tajemství výše.

Následující dvě anotace jsou vyžadovány v `Ingress`.

```yaml copy
    nginx.ingress.kubernetes.io/auth-type: basic
    nginx.ingress.kubernetes.io/auth-secret: secretref
```

`secretref` musí odpovídat názvu metadat `Secret`.

❗ **Omezení:**

Ochrana heslem se vztahuje pouze na externí provoz, tj. uživatel bude vyzván k zadání hesla. Provoz z jiných podů však obchází autentizaci, pokud komunikuje přímo s IP adresou `Service`. To lze zmírnit použitím `Network Policy`. Viz [Bezpečnost](./security).

### Nahrávání velkých dat

Pokud se očekává nahrávání velkých dat, mohou být vyžadovány následující dvě anotace `Ingress`, aby se vyřešil limit velikosti nahrávání.

```yaml copy
nginx.ingress.kubernetes.io/proxy-body-size: "600m"
nginx.org/client-max-body-size: "600m"
```

Nahraďte hodnotu `600m` požadovanou maximální velikostí nahrávání.

### HTTPS Cíl

Objekt Ingress může vystavit aplikace, které používají protokol HTTPS místo HTTP, tj. komunikace mezi ingress a aplikací je také šifrovaná. V tomto případě je nutné přidat anotaci `nginx.ingress.kubernetes.io/backend-protocol: "HTTPS"` k objektu ingress.

### Omezování externího síťového přístupu

Je možné omezit přístup k webové aplikaci na úrovni ingress tím, že omezíte přístup z konkrétního rozsahu IP adres. To se provádí pomocí anotace `Ingress` `nginx.ingress.kubernetes.io/whitelist-source-range`, následující příklad omezuje přístup pouze z MUNI sítě.

```yaml title="ingress.yaml"
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: application-ingress
  annotations:
    kubernetes.io/tls-acme: "true"
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
    nginx.ingress.kubernetes.io/whitelist-source-range: 147.251.0.0/16
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - "my-name"
      secretName: my-name-tls
  rules:
  - host: "my-name"
    http:
      paths:
      - backend:
          service:
            name: application-svc
            port:
              number: 80
        pathType: ImplementationSpecific
```

### Ladění: Certifikát nebyl vydán

Pokud jste vše nakonfigurovali podle dokumentace, certifikát by měl být vydán během několika okamžiků. Pokud certifikát nebyl vydán, je možné, že pod, který má sloužit `acme-challenge` (tedy vydat certifikát), nemůže být nasazen ve vašem namespace kvůli plné kvótě zdrojů namespace. Tento nový pod vyžaduje `100MiB` paměti a `100m` CPU, takže pokud je váš namespace plně rezervován, zkuste zvýšit [kvótu zdrojů namespace](../rancher/quotas#changing-namespace-quotas) (přidejte `100` k rezervaci paměti a limitu paměti; přidejte `100` k rezervaci CPU a limitu CPU) nebo odeberte některé nasazení z namespace.

Pokud máte nainstalovaný `kubectl`, můžete zkontrolovat, zda je to problém:

1. Zkontrolujte, zda je vytvoření Ingressu uvízlé na acme-solver (`kubectl get ingress -n [your_namespace]` vrátí řádek obsahující `cm-acme-http-solver`)

```bash
> kubectl get ingress -n [your_namespace]
NAME                        CLASS    HOSTS                                                                             ADDRESS                PORTS     AGE
cm-acme-http-solver-972p9   <none>   schema.biodata.ceitec.cz                                                          kuba-pub.cerit-sc.cz   80        12m
```

2. Vylistujte události, které se dějí ve vašem namespace a zjistěte, zda je tam varování o kvótách (`kubectl get events -n [your_namespace]` bude obsahovat nějaké řádky s `exceeded quota`)

```bash
> kubectl get events -n [your_namespace] | grep cm-acme-http-solver
...
79s         Warning   PresentError   challenge/adamant-dyn-cloud-e-infra-cz-6dp4n-152868974-3440702542   (combined from similar events): Error presenting challenge: pods "cm-acme-http-solver-74szl" is forbidden: exceeded quota: default-kn7vq, requested: limits.cpu=100m, used: limits.cpu=1, limited: limits.cpu=1
...
```

Události je také možné zkontrolovat z uživatelského rozhraní Rancher.

![acmesolver](/img/ceritsc/acme-solver.png)

### Vlastní chybové stránky

V některých případech může `Ingress` vrátit výchozí chybovou stránku NGINX namísto vaší vlastní chybové stránky. Tento problém může nastat, pokud chybová stránka (například `404.html` nebo `500.html`) je menší než `8 KiB`. NGINX má výchozí minimální velikost pro správné fungování chybových stránek.

#### Řešení

Pro řešení tohoto problému můžete upravit anotace `Ingress` tak, aby zahrnovaly:

```yaml copy
nginx.ingress.kubernetes.io/server-snippet: |
  proxy_intercept_errors on;
  proxy_pass_request_body on;
```

#### Příklad

```yaml title="ingress.yaml"
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: application-ingress
  annotations:
    kubernetes.io/tls-acme: "true"
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
    nginx.ingress.kubernetes.io/server-snippet: |
      proxy_intercept_errors on;
      proxy_pass_request_body on;
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - "my-name"
      secretName: my-name-tls
  rules:
  - host: "my-name"
    http:
      paths:
      - backend:
          service:
            name: application-svc
            port:
              number: 80
        pathType: ImplementationSpecific
```

## Ostatní aplikace

Aplikace, které nepoužívají protokol `HTTP`, jsou vystaveny přímo prostřednictvím `Service`.

```yaml title="service.yaml"
apiVersion: v1
kind: Service
metadata:
  name: application-svc
  annotations:
    external-dns.alpha.kubernetes.io/hostname: application.dyn.cloud.e-infra.cz
spec:
  type: LoadBalancer
  ports:
  - port: 22
    targetPort: 2222
  selector:
    app: application
```

Kde `selector: app: application` musí odpovídat názvu aplikace v nasazení a `application-svc` je libovolný název. Pokud je poskytnuta anotace `external-dns.alpha.kubernetes.io/hostname` a hodnota je v doméně `dyn.cloud.e-infra.cz`, název bude zaregistrován v DNS.

Nasazení tohoto *Service* vystavuje aplikaci na veřejné IP. Můžete zkontrolovat IP pomocí `kubectl get svc -n namespace`, kde `namespace` je namespace služby a aplikace.

### Kontrola přiřazené veřejné IP

```bash
> kubectl get svc -n [your_namespace]
NAME              TYPE           CLUSTER-IP      EXTERNAL-IP     PORT(S)        AGE
application-svc   LoadBalancer   10.11.12.13     9.8.7.6         22:31234/TCP   2m
```

Ve výše uvedeném příkladu je EXTERNAL-IP `9.8.7.6`.

### Privátní MUNI IP

Je také možné vystavit aplikaci na soukromé MUNI IP. V tomto případě bude aplikace dostupná z MUNI sítě nebo pomocí MUNI VPN. Tento typ vystavení je vybrán pomocí anotace `metallb.io/address-pool: privmuni`. Tento případ je preferován, protože nepoužívá veřejnou IP. Úplný příklad je níže.

```yaml title="service.yaml"
apiVersion: v1
kind: Service
metadata:
  name: application-svc
  annotations:
    metallb.io/address-pool: privmuni
    external-dns.alpha.kubernetes.io/hostname: application.dyn.cloud.e-infra.cz
spec:
  type: LoadBalancer
  ports:
  - port: 22
    targetPort: 2222
  selector:
    app: application
```

### LoadBalancer Firewall

Pokud vaše služba komunikuje na portu `5432` a chcete zabránit přístupu z konkrétních IP adres, můžete použít anotaci `metallb.universe.tf/loadBalancerSourceRanges`. Následující příklad umožňuje přístup pouze z MUNI sítě:

```yaml title="service.yaml"
apiVersion: v1
kind: Service
metadata:
  name: application-svc
  annotations:
    metallb.io/address-pool: privmuni
    external-dns.alpha.kubernetes.io/hostname: application.dyn.cloud.e-infra.cz
spec:
  type: LoadBalancer
  loadBalancerSourceRanges:
    - 147.251.0.0/16
  ports:
  - port: 22
    targetPort: 2222
  selector:
    app: application
```

### Sdílení IP adresy napříč více službami

Pokud potřebujete otevřít více než jednu službu na stejné IP adrese, můžete sdílet IP adresu napříč `Services`. Sdílení IP vyžaduje:

1. Anotaci `metallb.io/allow-shared-ip: [key]` přidanou ke všem `Services`, které sdílejí IP.
2. Stejnou hodnotu `key` pro všechny `Services`, které mají sdílet IP.
3. Všechny `Services` musí být ve stejném namespace.

Následující příklad ukazuje `Services` sdílející IP adresu pomocí klíče `my-shared-key-for-application`:

```yaml title="service-read.yaml"
apiVersion: v1
kind: Service
metadata:
  name: application-read-svc
  annotations:
    external-dns.alpha.kubernetes.io/hostname: application.dyn.cloud.e-infra.cz
    metallb.io/allow-shared-ip: [my-shared-key-for-application]
spec:
  type: LoadBalancer
  allocateLoadBalancerNodePorts: false
  externalTrafficPolicy: Cluster
  ports:
  - port: 5433
    targetPort: 5432
  selector:
    app: application-ro
```

```yaml title="service-write.yaml"
apiVersion: v1
kind: Service
metadata:
  name: application-write-svc
  annotations:
    external-dns.alpha.kubernetes.io/hostname: application.dyn.cloud.e-infra.cz
    metallb.io/allow-shared-ip: [my-shared-key-for-application]
spec:
  type: LoadBalancer
  allocateLoadBalancerNodePorts: false
  externalTrafficPolicy: Cluster
  ports:
  - port: 5433
    targetPort: 5432
  selector:
    app: application-rw
```

#### Omezení

- Pokud je `externalTrafficPolicy` nastaven na `Local`, **všechny cílové Pody musí být naplánovány na stejný uzel**, aby byla zajištěna dostupnost.
- Pokud je `externalTrafficPolicy` nastaven na `Cluster`, **Pody mohou být distribuovány napříč více uzly**, což zlepšuje odolnost a distribuci zatížení.
