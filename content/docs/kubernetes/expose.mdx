---
title: Exposing Applications
---

This chapter explains how to configure external access to your application from an external network. There are two main types of applications that can be exposed. The primary distinction between them is their IP address requirements — web-based applications share a single IP address with all other web-based applications (via the cluster's HTTP load balancer), whereas non-HTTP applications require a dedicated IP address for each service.

The content is split into two separate pages:

- **[Exposing HTTP Applications](./expose-http)** — web applications, REST APIs, dashboards, etc. using Gateway API (HTTPRoute), Traefik IngressRoute, or nginx Ingress (`nginx-traefik`).
- **[Exposing Non-HTTP Applications](./expose-network)** — SSH, databases, message brokers, custom TCP/UDP protocols, exposed via `LoadBalancer` Services.

Since the number of available dedicated IP addresses is limited, prefer HTTP whenever possible.

<Callout title="Prerequisite" icon="✅">
These guides assume that your application (`Deployment`) is already deployed. If you are unsure, refer to the [Hello World example](../examples/helloworld).
</Callout>

Throughout the sub-pages, YAML fragments are provided. Deploy them using:

```shell
kubectl create -f file.yaml -n namespace
```
