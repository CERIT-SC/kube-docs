title: MPI Operator

While [MPI](https://www.openmpi.org/) jobs are a traditional domain in High-Performance Computing, our platform is capable of running MPI jobs easily using the MPI Operator from [Kubeflow](https://www.kubeflow.org). The [MPI Operator](https://github.com/kubeflow/mpi-operator) makes it easy to run allreduce-style distributed training on Kubernetes. We have deployed a cluster-wide MPI Operator which allows you to create an MPI job by defining a Kubernetes kind `MPIJob`. Full documentation on the kind's structure is available [here](https://github.com/kubeflow/mpi-operator/blob/master/manifests/base/kubeflow.org_mpijobs.yaml). Some documentation on the MPI Operator can be found at the [Kubeflow site](https://www.kubeflow.org/docs/components/training/mpi/#creating-an-mpi-job) or [this blog post](https://medium.com/kubeflow/introduction-to-kubeflow-mpi-operator-and-industry-adoption-2965f2e6edc).

To be able to run an MPI job, there are two steps required: prepare a specific Docker image and create an MPIJob manifest.

## MPI Job Docker Image

MPIJob expects a specific Docker image; the image must contain an OpenSSH server and this server needs to be configured. Also, creating a user in the Docker image is required. However, you need to add the following fragment for Debian family distributions ([download here](/examples/ceritsc/docker/Dockerfile-mpi)):

```dockerfile
RUN apt-get update && \
    apt-get -y --no-install-recommends install openmpi-bin openssh-server openssh-client bind9-host && \
    apt-get clean && rm -rf /var/lib/apt/lists/*

RUN mkdir -p /var/run/sshd

RUN useradd -m -u 1000 user

RUN sed -i 's/[ #]\(.*StrictHostKeyChecking \).*/ \1no/g' /etc/ssh/ssh_config && \
    echo "    UserKnownHostsFile /dev/null" >> /etc/ssh/ssh_config && \
    echo "StrictModes no" > /etc/ssh/sshd_config && \
    echo "PidFile /tmp/sshd.pid" >> /etc/ssh/sshd_config && \
    echo "HostKey ~/.ssh/id_rsa" >> /etc/ssh/sshd_config && \
    echo "Port 2222" >> /etc/ssh/sshd_config && \
    echo "ListenAddress 0.0.0.0" >> /etc/ssh/sshd_config && \
    sed -i 's/.*Port 22.*/   Port 2222/g' /etc/ssh/ssh_config

WORKDIR /data

RUN chown 1000:1000 /etc/ssh/ssh_config

CMD /usr/sbin/sshd -De
```

Of course, you need to add your application and base a proper image like `tensorflow` or `pytorch`. The same image should be used for both `Launcher` and `Worker` Pods.

## MPI Job Manifest

You can [download](/examples/ceritsc/manifests/mpijob.yaml) an example of an MPI Job manifest. This example is **not working** as is. You need to specify `IMAGE` and `COMMAND`. The user in the attribute `sshAuthMountPath` must match the user name created in the Docker image. The attribute `Worker.replicas` denotes how many workers to spawn, that is, how many parallel jobs will run. Also the parameter `-n "2"` for `Launcher` needs to match `Worker.replicas`. Note, the number `"2"` must always be quoted.

## Running the MPI Job

Once you have the Docker image and the manifest ready, you run the MPI Job using:
```bash
kubectl create -f mpijob.yaml -n namespace
```
replacing `namespace` with your namespace. The *Launcher* jobs might be failing for a while; this is expected and normal.
