---
title: Ukládání Kubernetes Secretů v Gitu
---

Jakmile máte nakonfigurovanou Kubernetes aplikaci, pravděpodobně budete chtít její YAML soubory uložit v git repozitáři pro účely správy verzí.
S tajemstvími (Secrets) však narazíme na problém. Ukládání YAML souborů s tajemstvími v gitu je špatný nápad, protože pokud někdo získá přístup k našemu
git repozitáři, bude moci tajemství prohlížet v čitelném textu.

Tento článek vysvětluje, jak bezpečně ukládat Kubernetes Secrets v gitu.

## Předpoklady

- Jmenný prostor ve vašem clusteru
- kubectl
- kubeseal

## Instalace kubeseal

Pro bezpečné ukládání tajemství budete potřebovat program `kubeseal`. Tento program lze stáhnout jako samostatný binární soubor z tohoto [GitHub repozitáře](https://github.com/bitnami-labs/sealed-secrets/releases).

## Jak uložit vaše tajemství

Nejprve budete potřebovat YAML soubor definující vaše tajemství, například tento (všimněte si, že data tajemství musí být zakódována v base64):

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: my-very-secret-data
  namespace: my-namespace
type: Opaque
data:
  universe: NDIK
```

Nyní převedete své tajemství na `Sealed Secret`. To znamená, že data vašeho tajemství budou zašifrována pomocí náhodně vybraného klíče. Tento klíč bude následně zašifrován pomocí veřejného šifrovacího klíče Kubernetes a připojen k zapečetěnému tajemství. V tomto okamžiku bude pouze Kubernetes schopen dešifrovat obsah tajemství pomocí svého soukromého dešifrovacího klíče, a proto je bezpečné uložit zapečetěné tajemství uvnitř git repozitáře.

Své tajemství můžete převést na zapečetěné tajemství zadáním tohoto příkazu:

`kubeseal --controller-namespace sealed-secrets-operator < my-secret.yaml > sealed-secret.json`

`kubectl apply -f sealed-secret.json -n my-namespace`

## Zabezpečení

<Callout type="warn">
Společně se šifrovacím klíčem jsou také zašifrovány název tajemství a zamýšlený jmenný prostor a přidány k `Sealed Secret`. Tím je zajištěno, že zapečetěné tajemství může být nainstalováno pouze do původně zamýšleného jmenného prostoru. Tím se zabrání zlomyslným uživatelům aplikovat vaše zapečetěné tajemství do svého jmenného prostoru za účelem zobrazení dešifrovaných dat.
</Callout>
