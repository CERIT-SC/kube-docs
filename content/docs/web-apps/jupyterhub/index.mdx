**JupyterHub** at CERIT-SC provides researchers and scientists with instant, browser-based access to interactive computing environments (JupyterLab, RStudio, MATLAB, and VS Code) backed by high-performance CPU and GPU resources.

To accelerate your research, our platform features **built-in, on-premise Generative AI assistants** (Jupyter AI, Claude Code, and Posit Assistant). Because our Large Language Models (LLMs) run entirely on CERIT-SC infrastructure, your unpublished research data, sensitive datasets, and proprietary code never leave our servers.

---

## 1. Quick Start: Launching Your Environment

To access JupyterHub, you must have an active **MetaCentrum** account.

1. Log in at **[hub.cloud.e-infra.cz](https://hub.cloud.e-infra.cz/)**.
2. **Quick Launch:** Click **`My Server`** to start a default environment immediately.
3. **Custom Launch (Recommended):** To run multiple environments or customize your setup, enter a short, descriptive name under **Add new server** and click the button to configure your instance.

---

## 2. Configuring Your Server

When spawning a new server, you will configure three main components: your **Software Image**, **Storage**, and **Hardware Resources**.

### Step A: Choose Your Image
Select a pre-configured environment tailored to your scientific domain:

| Category | Image Options | Best For |
| :--- | :--- | :--- |
| **AI-Enhanced Python / Data Science** | `Minimal NB AI`, `DataScience NB AI` | General data analysis, Python coding with built-in **Jupyter AI** chat and **Claude Code** agentic assistant. |
| **Statistical Computing (R)** | `RStudio-AI` (`4.6.1`), `cerit.io/hubs/rstudio:4.5.2-ai` | R programming with **Posit Assistant** or **Claude Code** integration. |
| **Machine & Deep Learning** | `TensorFlow`, `PyTorch` (look for `...with GPU...`) | Training neural networks and GPU-accelerated calculations. |
| **Structural Biology** | `Folding images` (ColabFold / ESMFold) | Protein structure prediction and bioinformatics. |
| **Engineering & Math** | `Matlab` | Interactive, full graphical MATLAB desktop environment in your browser. |
| **Remote Development** | `Minimal NB with SSH access` | Connecting your local IDE (e.g., local VS Code or PyCharm) via SSH. |

> **Using a Custom Docker Image:** You can supply your own public Docker image in the format `repo/imagename:tag` (e.g., hosted on Docker Hub or the [CERIT-SC Harbor registry](../docker/harbor)). Always build on top of an [existing Jupyter Docker Stack image](https://jupyter-docker-stacks.readthedocs.io/en/latest/using/selecting.html) to ensure all required JupyterHub startup scripts are present.

![JupyterLab Launcher](/img/ceritsc/apps/jupyterhub/lab.png)

### Step B: Configure Storage
* **Default Persistent Storage (`/home/jovyan`):** Every notebook automatically mounts a persistent disk at `/home/jovyan` (or `/home/rstudio` in RStudio). **Always save your scripts and results here** so they persist when your server stops. You can also reuse and share this storage across different notebook instances.
* **MetaCentrum Home (`/home/meta/<username>`):** You can mount one MetaCentrum storage home or project directory per notebook to access your existing grid files directly.

<Callout type="warning">
**Prevent Spawn Failures:** Only select a MetaCentrum storage location where you actually have an existing home directory. Selecting an uninitialized storage location will cause your server startup to fail.  If you are not sure about home location, contact <a href="mailto:k8s@cerit-sc.cz">IT Service desk</a> who will help.
</Callout>


### Step C: Allocate Hardware Resources (CPU, RAM, GPU)
Request only what your current workflow requires:
* **CPU (Guaranteed: 1 | Max: 32):** Soft-handled. If your code exceeds your CPU limit, your notebook **will not crash**—the computation will simply be throttled (run slower).
* **RAM / Memory (Guaranteed: 4 GB | Max: 256 GB):** Hard limit. **Warning:** If your code consumes more RAM than allocated, the kernel/process will be abruptly terminated (Out-Of-Memory error), though your notebook interface will stay open.
* **GPU (Whole GPU or NVIDIA MIG Slices):**
  * **Whole GPU:** Only select a GPU if you are also selecting a GPU-enabled image (marked with `...with GPU...`), which includes the necessary CUDA drivers.
  * **NVIDIA MIG (Multi-Instance GPU):** Ideal for smaller models or testing. You can request isolated hardware slices of an NVIDIA A100 (80 GB) card—up to 4 slices of `10GB part A100` or `20GB part A100`. Each slice acts as an independent GPU with dedicated memory. *(Note: Using more than 1 MIG slice requires multi-GPU support in your code).*

## 3. Using On-Premise AI Assistants in Your Research

<Callout type="info">
**100% Data Privacy for Scientists:** All AI models offered in JupyterHub run on CERIT-SC’s internal, on-premise LLM infrastructure. No code, prompts, or research datasets are ever sent to external providers (like OpenAI or Anthropic).
</Callout>

### Option 1: Jupyter AI (Chat & Cell Magic in JupyterLab)
**Best for:** Generating plotting code, explaining errors, writing documentation, and quick code snippets.

1. Spawn a server using the **`DataScience NB AI`** image.
2. Look for the **Jupyternaut** chat icon in the left sidebar to open an interactive chat panel.


#### Try It Out: Practical Examples
* **Sidebar Chat:** Click the chat icon, highlight a block of messy analysis code in your notebook, and ask:
  > *"Refactor this pandas code to be faster and add docstrings explaining the statistical transformations."*
* **Learn from Local Files:** In the chat panel, type `/learn` followed by a path to your local documentation or `.py` scripts so the assistant can answer questions about your specific codebase.
* **In-Cell `%%ai` Magic:** You can prompt the LLM directly inside a notebook code cell (refer to the [Jupyter AI docs](https://jupyter-ai.readthedocs.io/en/latest/) for full syntax):
  ```python
  # Load the AI extension in a cell, then generate a publication-ready plot:
  %load_ext jupyter_ai_magics
  ```
  ```python
  %%ai
  Write Python code using seaborn and matplotlib to create a Raincloud plot 
  comparing gene expression levels across 3 treatment groups from a DataFrame `df`.
  Include ANOVA p-value annotations.
  ```

### Option 2: Claude Code (Agentic AI for Complex Workflows)
**Best for:** Multi-file refactoring, building end-to-end data pipelines, debugging across scripts, and exploring unfamiliar datasets.

Unlike a simple chat window, **Claude Code** is an agentic assistant that can read your notebooks, inspect data schemas, and navigate your project directory. 
* **Human-in-the-Loop Safety:** Claude Code **cannot** execute notebook cells or modify critical files without your explicit approval. It will always ask for your permission before making changes.

#### Launching Claude Code in JupyterLab
1. Start a server with the **`DataScience NB AI`** image.
2. Open your project folder (working inside a dedicated project folder helps the agent understand your file structure).
3. Open a terminal or the Claude interface to begin interacting with your codebase. *(See the [e-INFRA CZ Blog](https://blog.cerit.io/blog/claude-jupyter/) for more visual walkthroughs).*

3. Open the **Terminal** tab inside RStudio, type `claude`, and press **Enter**:

#### Try It Out: Example Prompts for Claude Code
Once `claude` is running in your project terminal, try typing natural-language tasks:
* **Data Cleaning Pipeline:**
  > *"Inspect the CSV files in `./raw_data/`. Some have missing timestamps and inconsistent column names. Write a Python script `clean_data.py` to standardize them and save the output as a Parquet file."*

  > *"Read `simulation.py`. It runs out of memory when `N > 10000`. Identify the memory bottleneck and rewrite it using NumPy vectorization or chunking."*

</Callout>

## 4. Common Scientific Workflows & Customization

### Managing Custom Conda Environments
All images support `conda`. If you need specific library versions (e.g., `scanpy`, `biopython`, or a specific `scikit-learn`) that remain available across sessions, create a custom kernel:

1. Open a **Terminal** in JupyterLab and initialize Conda:
   ```bash
   conda init
   ```
2. Create a new environment. **Important:** You must include `ipykernel` and `nb_conda_kernels` (or `irkernel` for R) so Jupyter can see the environment:
   ```bash
   conda create -n bio_env --yes python=3.10 ipykernel nb_conda_kernels biopython scipy
   ```
   ![moveenv](/img/ceritsc/apps/jupyterhub/move_env.png)
3. Verify your environment is listed:
   ```bash
   conda env list
   ```
   ![checkenv](/img/ceritsc/apps/jupyterhub/check_env.png)
4. Install additional packages anytime with:
   ```bash
   conda install -n bio_env seaborn
   ```
5. Switch your notebook to the new environment via the top menu: **Kernel &rarr; Change Kernel...** and select `bio_env`.
   ![selenv](/img/ceritsc/apps/jupyterhub/select_env.png)

### Running Interactive Dashboards (Streamlit, Dash, Gradio) via Flare
If you build an interactive web app inside your notebook (such as a **Streamlit** data explorer, **Plotly Dash** app, or **Gradio** ML demo), you can expose it to a public URL using our `flare` tunnel tool:

1. In your Jupyter terminal, install `flare`:
   ```bash
   pip install git+[https://github.com/CERIT-SC/flare](https://github.com/CERIT-SC/flare)
   ```
2. Start your web application in the background (for example, a Streamlit app running on port `8501`):
   ```bash
   streamlit run app.py --server.port 8501 &
   ```
3. Expose the port using `flare`:
   ```bash
   flare tunnel --port 8501 --name my-lab-dashboard
   ```
   Your interactive app is now live at **`https://my-lab-dashboard.flare.cloud.e-infra.cz`**!

### Offloading Heavy Computations to Background Kubernetes Jobs
Jupyter notebooks are ideal for interactive exploration, but if you have a script that takes days to run or requires heavy resources, **offload it as a background Kubernetes `Job`**. This keeps your interactive notebook responsive and avoids holding onto large resource allocations unnecessarily.

#### Step 1: Set Up `kubectl` in Your Terminal
*(Note: For RStudio images, run these commands in the terminal to install and configure `kubectl`):*
```bash
# 1. Download kubectl (if curl is missing, run: fakeroot apt-get update && fakeroot apt-get install -y curl)
curl -LO "[https://dl.k8s.io/release/$(curl](https://dl.k8s.io/release/$(curl) -L -s [https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl](https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl)"

# 2. Install kubectl
fakeroot install -o rstudio -m 0755 kubectl /usr/local/bin/kubectl

# 3. Configure cluster environment variables
export KUBERNETES_PORT=tcp://10.43.0.1:443 KUBERNETES_PORT_443_TCP=tcp://10.43.0.1:443 \
       KUBERNETES_PORT_443_TCP_ADDR=10.43.0.1 KUBERNETES_PORT_443_TCP_PORT=443 \
       KUBERNETES_PORT_443_TCP_PROTO=tcp KUBERNETES_SERVICE_HOST=10.43.0.1 \
       KUBERNETES_SERVICE_PORT=443 KUBERNETES_SERVICE_PORT_HTTPS=443

# 4. Verify connection (should list your running notebook pods)
kubectl get pods
```

#### Step 2: Find Your Storage Volume Names (PVCs)
To let your background Job read your scripts and write output directly back to your notebook's folders, locate the `PersistentVolumeClaim` (PVC) names for your storage:

* **Find your Notebook Home PVC (`/home/jovyan` or `/home/rstudio`):**
  ```bash
  kubectl get pvc | awk -v volume=$(df -h | awk '$1 ~ /^147\.251\.6\.218:/ {split($1, a, "/"); print a[length(a)]}') '$3 == volume {print $1}'
  # Example output: testuser-home-pipemaster
  ```
* **Find your MetaCentrum Home PVC (`/home/meta/<username>`):**
  ```bash
  # 1. Check which MetaCentrum storage server is mounted:
  df -h | awk '$NF ~ /^\/home\/meta/ {match($1, /@([^:]+):/, m); print m[1]}'
  # Example output: storage-brno2.metacentrum.cz

  # 2. List your SSHFS claims and match the server name (e.g., brno2):
  kubectl get pvc | awk '$3 ~ /-data-sshfs$/ {print $1}'
  # Example output: testuser-brno2-claim
  ```

#### Step 3: Define Your Job
When creating your Kubernetes Job manifest, specify four items: (1) the **Docker image** containing your libraries, (2) the **command/script** to execute, (3) **CPU/RAM resources**, and (4) the **PVC volume mounts** discovered in Step 2 so outputs are written directly back to your notebook directory. *(Need help writing a Job manifest? Contact **k8s@cerit-sc.cz**).*

## 5. Advanced: SSH Access & Custom Images

### Connecting via SSH
You can connect to your notebook environment via SSH (e.g., to use VS Code Remote-SSH from your laptop).

<Callout type="warning">
**IPv6 Required:** SSH access works **only from IPv6-enabled networks**. If you are on an IPv4-only home network, connect via **eduVPN** first.
</Callout>

1. Spawn a server using the **`Minimal NB with SSH access`** image.
2. **Copy the SSH address** shown during startup (e.g., `jovyan@jupyter-xhejtman---54est.dyn.cloud.e-infra.cz`)—it will not be shown in the UI again. *(If you lose it, run `kubectl get svc -n jupyterhub-[yourlogin]-prod-ns -o yaml | grep external-dns.alpha.kubernetes.io/hostname` inside the notebook).*
   ![ssh](/img/ceritsc/apps/jupyterhub/ssh.png)
3. Inside the JupyterLab terminal, add your laptop's public SSH key (`~/.ssh/id_rsa.pub`) to `/home/jovyan/.ssh/authorized_keys`:
   ```bash
   mkdir -p ~/.ssh
   echo "ssh-rsa AAAA...your-public-key..." >> ~/.ssh/authorized_keys
   ```
4. Verify that the `sshd` daemon is running using `ps -fax`. If you do not see `/usr/sbin/sshd` in the list, start it manually by running `/usr/sbin/sshd` in the notebook terminal.
5. Connect from your laptop terminal:
   ```bash
   ssh jovyan@jupyter-xhejtman---54est.dyn.cloud.e-infra.cz
   ```

### Building Your Own Custom Docker Image
* **Standard Custom Image:** Base your `Dockerfile` on `jupyter/minimal-notebook:hub-4.0.2` (see our [example Dockerfile](/examples/ceritsc/jupyterhub/Dockerfile-minimal)). If building from another base image, install `jupyterlab` and copy [start-notebook.py](/examples/ceritsc/jupyterhub/start-notebook.py), [start-notebook.sh](/examples/ceritsc/jupyterhub/start-notebook.sh), [start-singleuser.py](/examples/ceritsc/jupyterhub/start-singleuser.py), [start-singleuser.sh](/examples/ceritsc/jupyterhub/start-singleuser.sh), and [start.sh](/examples/ceritsc/jupyterhub/start.sh) into `/usr/local/bin` with Unix (`LF`) line endings and executable permissions (`chmod a+rx /usr/local/bin/start*`).
* **Custom SSH-Enabled Image:** Base your image on `cerit.io/hubs/minimalnb:26-09-2024-ssh`, or install `openssh-server` in your custom image:
  1. Add this configuration to `/etc/ssh/sshd_config.d/sshd.conf` (or `/etc/ssh/sshd_config`):
     ```ini title="sshd.conf"
     Port 2222
     AddressFamily any
     ListenAddress 0.0.0.0
     ListenAddress ::
     StrictModes no
     PubkeyAuthentication yes
     UsePAM yes
     X11Forwarding no
     PrintMotd no
     TCPKeepAlive yes
     PubkeyAcceptedKeyTypes +ssh-rsa
     ```
  2. **Security Requirement:** Delete all existing `/etc/ssh/ssh_host_*` files during the Docker build and regenerate them dynamically at container startup in `/usr/local/bin/start-notebook.sh`:
     ```bash title="start-notebook.sh"
     #!/bin/bash
     echo "WARNING: Use start-notebook.py instead"

     (export LD_LIBRARY_PATH=''; 
      rm -f /etc/ssh/ssh_host_*; 
      for i in rsa dsa ecdsa ed25519; do 
        ssh-keygen -q -f /etc/ssh/ssh_host_${i}_key -N '' -t $i; 
        ssh-keygen -f /etc/ssh/ssh_host_${i}_key.pub; 
      done)

     LD_LIBRARY_PATH='' /usr/sbin/sshd

     exec /usr/local/bin/start-notebook.py "$@"
     ```

## 6. Server Management & Automatic Idle Shutdown

### Managing Running Servers
To stop, delete, or add servers at any time, go to **File &rarr; Hub Control Panel** in the top-left corner of JupyterLab, or visit **[hub.cloud.e-infra.cz/hub/home](https://hub.cloud.e-infra.cz/hub/home)** directly.
* **To delete an instance:** Click **`Stop`** next to the server name, wait a few seconds for the blue **`Delete`** button to appear, and click it. (Your persistent storage in `/home/jovyan` remains intact unless explicitly deleted during spawn).

![add1](/img/ceritsc/apps/jupyterhub/add1.png)
![add2](/img/ceritsc/apps/jupyterhub/add2.png)

### Automatic Idle Shutdown Policy
To ensure fair access to expensive cluster hardware (especially GPUs) for all researchers, an automated script evaluates active notebooks once every 24 hours (measuring peak 5-minute average utilization):

| Server Type | Idle Threshold | Grace Period Before Deletion |
| :--- | :--- | :--- |
| **Notebooks with GPU** | `< 0.005` GPU utilization (CPU usage is ignored) | **2 consecutive days** of inactivity|
| **CPU-Only Notebooks** | `< 0.1` CPU cores utilized | **4 consecutive days** of inactivity |

* **Email Warnings:** You will receive daily warning emails (sent to your preferred MetaCentrum email address) each day your notebook falls below the threshold, plus a final notification if the instance is deleted.
* **How to Keep Your Server Alive:** Simply running a calculation that exceeds the threshold resets your warning counter to zero automatically.

## 7. Troubleshooting Common Errors

| Error / Symptom | Likely Cause | How to Fix It |
| :--- | :--- | :--- |
| **`HTTP 500: Internal Server Error`** *(followed by `Error in Authenticator.pre_spawn_start`)* | 1. You selected a MetaCentrum storage home you haven't initialized recently.<br/>2. You selected a storage home you don't have permissions for. | 1. **Log out and log back in** to refresh your credentials.<br/>2. If it still fails, spawn a new server and choose a different MetaCentrum storage location where your home directory exists. |
| **`Error: ImagePullBackOff`** *(followed by `Spawn failed: pod/jupyter-[username] did not start in 600 seconds!`)* | You entered a custom Docker image name/tag with a typo, or the repository is private. | Expand the **`Event log`** arrow to verify the `[Warning]` message. Wait for the **10-minute timeout** to complete, reload the browser page, click **`Relaunch server`**, and correct the image name. |
