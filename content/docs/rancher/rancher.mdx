The _Rancher_ instance is available at [rancher.cloud.e-infra.cz](https://rancher.cloud.e-infra.cz). Log in using e-INFRA CZ, Life Science Login (ELIXIR), or EGI Check-In.

After logging in, you will see the default dashboard showing the available clusters. If no cluster appears, reload the page—it may take up to a minute for the clusters to load.

Rancher and Kubernetes organize resources into *clusters*, *Projects*, and *Namespaces*. *Clusters* correspond to groups of physical nodes. *Projects* are created within *clusters*, and *Namespaces* are created within *Projects*. *Projects* are a Rancher-only concept and are not native to Kubernetes. [Namespaces](https://kubernetes.io/docs/concepts/overview/working-with-objects/namespaces/) provide a mechanism to isolate groups of resources within a single cluster. Resource names must be unique within a namespace but not across namespaces. Namespace names must be unique within a cluster. For example, it is generally not advisable to create a namespace called *test*.

Each user receives a *Default Project* labeled with their first and last name, along with a default *Namespace* named `surname-ns`. The default Project and Namespace are automatically created when the user first logs into the Rancher dashboard. To create additional Namespaces, use the Rancher GUI: navigate to the namespace overview and click the `Create Namespace` button.

Do not use `kubectl` to create namespaces.


For more details about creating Namespaces and quotas, refer to the [quota](./quotas) documentation.

Many tasks can be performed directly through the Rancher interface. For more advanced operations, use the `kubectl` command-line tool. Both approaches are effective; however, we recommend Rancher for users who are less familiar with the terminal.
