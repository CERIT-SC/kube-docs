## Introduction

Chat AI](https://chat.ai.e-infra.cz) provides a browser interface to
AI models hosted by CERIT-SC within e-INFRA CZ. The interface, called
Open WebUI, lets you work with text, code, and documents without
installing software locally.

You can use it to revise scientific writing, explore programming
questions, extract information, and discuss research material.
Some models also support images or tools for calculations.

This guide explains how to get access, choose a model, and use the
main features. For scripts and automated workflows, see the
[OpenAI-compatible API guide](./ai-api).

## Data privacy

Before uploading research material, consider its sensitivity and
your project's data-handling requirements.

The standard hosted models run within e-INFRA CZ. However, external
search tools and separately arranged third-party services may send
information outside this infrastructure.

The chat interface stores conversations and uploaded files.
The [AI data privacy policy](./ai-data-privacy) describes storage,
logging, retention, and deletion limitations.

<Callout type="warning">
The chat interface is intended for general research assistance and
is not certified for protected data. Before submitting sensitive,
personal, classified, or otherwise restricted information, contact
[k8s@cerit-sc.cz](mailto:k8s@cerit-sc.cz) to discuss a suitable setup.
</Callout>

Direct API access bypasses the chat interface's conversation storage.
This does not, by itself, establish that a workflow meets your
data-protection requirements.

## Using AI Models

### Start your first conversation

1. Select a model from the menu at the top of the chat.
   Scroll through the menu to see additional models.
2. Describe your task and provide the context needed to answer it.
3. Specify the desired output, such as a paragraph, table, or code example.
4. Send your message.
5. Review the response and ask follow-up questions where needed.

For example:

```
Revise the following methods paragraph for clarity. Preserve all
numerical values, units, citations, and statements of uncertainty.
Do not add information. Return the revised paragraph and a short
list of changes.
```

### Choose a model for your task

| Task | What to look for |
| --- | --- |
| Revising text, summarising, or extracting information | A general-purpose text model |
| Explaining or debugging code | A model suited to coding |
| Working through a complex problem | A reasoning model, followed by independent verification |
| Reading an image or scanned page | A multimodal model with image support |
| Running a calculation through an enabled tool | A model that supports tool use |
| Building semantic search in an application | An embedding model accessed through the API |

Start with a model that meets your needs on a small, representative
sample. A larger or slower model does not necessarily produce better
results for every task.

Image understanding and image generation are separate capabilities.
To create or edit an image, use the image tool described in
[Examples](#examples).

## How models are added, upgraded, and removed

CERIT-SC evaluates new models using benchmarks, community feedback,
and their suitability for the available computing resources.

Because GPU capacity is shared and limited, model versions may be
replaced or retired. Maintenance or urgent infrastructure requirements
can also temporarily affect availability.

Changes are announced through the documentation and chat-interface
notices. Check the
[live status page](https://llm.ai.e-infra.cz/status/)
when planning a substantial workload.

### Preserve your research results

A model may change during a thesis, publication, or other research
project. For work that needs to be traceable:

- Record the exact model identifier and available metadata.
- Save prompts, relevant inputs, generation settings, and dates.
- Keep copies of outputs in accordance with your data-management plan.
- Re-evaluate your workflow after a model change.

Even with the same model, repeated requests may produce different outputs.

Contact [k8s@cerit-sc.cz](mailto:k8s@cerit-sc.cz) before starting
work that depends on long-term access to a particular model version.

## Examples

The examples below describe the documented interface.
Available controls depend on the selected model and enabled tools.

### Revise scientific writing

Provide the passage and specify what may change.

> Revise this abstract for clarity and concision. Preserve the
> scientific meaning, numerical results, citations, and uncertainty.
> Do not introduce new claims. Return the revised abstract followed
> by any ambiguities that need my attention.

Compare the revision with the original, particularly where it
describes results, limitations, or causal relationships.

### Explain or debug code

Include the relevant code, the expected behaviour, and any error
message. Remove credentials and other confidential information.

> Explain why this Python function fails for an empty input.
> Suggest the smallest correction and provide examples covering
> an empty input, one value, and multiple values.

Review and test generated code before using it in an analysis.

### Image-to-text (OCR scanner)

Use a model with image support to extract text from a scanned page
or photograph.

1. Select a multimodal model.
2. Select **+ → Upload Files** and upload the image.
3. Describe the extraction task.
4. Send the request and compare the output with the source.

Example:

> Transcribe the text in this image. Preserve headings, line breaks,
> numerical values, and units. Mark unreadable text as [unclear]
> instead of guessing.

Check mathematical symbols, decimal separators, subscripts, and
table alignment carefully.

For a scanned PDF, check whether direct upload works with your selected
model and tool configuration. Individual page images can be used
when necessary.

### Image generation

Use the image tool to create illustrations for teaching, communication,
or early design work.

1. Select a chat model.
2. Open the **Integration** control and enable **Image**.
3. Describe the image you want.
4. Send the request.
5. Refine the result with follow-up instructions.

<div className="max-w-lg">

Example:

> Create a simple illustration of a researcher using a notebook,
> a computing cluster, and a document collection. Use a white
> background, blue accents, and no text.

Generated illustrations should not be presented as experimental
observations. Use plotting or diagramming software when values,
geometry, or scientific relationships must be exact.

### Picture editor

1. Select a model with image support.
2. Select **+ → Upload Files** and upload an image.
3. Open **Integration** and enable **Image**.
4. Specify the changes and what should remain unchanged.
5. Send the request and inspect the result.

Example:

> Change the background of this conceptual illustration to white.
> Preserve the objects, their positions, and their colours.

Keep the original file. Inspect details that the tool may have
changed unintentionally.

### Python sandbox for math/code tasks

The Python sandbox supports specific calculations and data
transformations with text output. It is not a general-purpose
programming environment.

1. Select a model that supports tools.
2. Open **Integration → Tools**.
3. Enable **Python Sandbox**.
4. Describe the calculation and provide the required data.
5. Inspect the calculation and its output.

<div className="max-w-lg">

![Python Sandbox tool selection in Chat AI](/img/ceritsc/python-webui.png)

</div>

Example:

> Calculate the mean and sample standard deviation of these
> measurements: 2.1, 2.4, 2.2, 2.6, and 2.3.
> Show the Python code and state which standard-deviation convention
> you used.

The documented sandbox returns text and does not render plots.
For plotting or a reproducible analysis environment, use
[JupyterHub](../web-apps/jupyterhub) or your own Python or R setup.

### Memorize (personalization)

Memory can retain preferences for later conversations, where supported.
For example, you might store that you prefer Python examples or
British English.

1. Open your user menu.
2. Go to **Settings → Personalization → Memory**.
3. Enable memory if it is available.
4. Use **Manage** to review and edit stored preferences.

<div className="max-w-lg">

![Memory settings in Chat AI](/img/ceritsc/memory-webui.png)

</div>

Memory support depends on the configured model and interface.
Check that a preference has been saved rather than relying only on
the model's acknowledgement.

Do not store passwords, API keys, or other credentials in memory.
For reproducible work, include important instructions explicitly
in the prompt rather than relying on personalisation.

## Knowledge function (alpha)

The experimental Knowledge function lets you query a collection
of uploaded documents using retrieval-augmented generation (RAG).

RAG retrieves relevant passages and supplies them as context to
a model. Uploading documents does not mean that the model has been
trained on them.

<Callout type="info">
The Knowledge function is intended for testing and preview.
It is not currently recommended for production workflows.
</Callout>

The documented setup uses a shared embedding-model configuration.
Changing that model can require documents to be processed again.

Retrieval quality depends on the language, document structure,
text extraction, and how documents are split into passages.
Test representative material before relying on the results.

Check answers against the original passages. Retrieved text and
citations do not guarantee that the model's interpretation is correct.

Before uploading a document collection, review the
[data privacy policy](./ai-data-privacy), including file-retention
and deletion limitations.

## Creating an API key

An API key lets your scripts and applications authenticate to the
AI service.

1. Open **Settings** in Chat AI.
2. Select **Account**.
3. Open **API keys**.
4. Generate a key or display an existing one.
   Use the API key rather than the separately displayed JWT token.
5. Store the key securely and configure your application to use it.

The documented API base URL is:

```text
https://llm.ai.e-infra.cz/v1/
```

Do not share API keys or include them in notebooks, source repositories,
screenshots, or chat messages. Use an environment variable or a
suitable secret-management mechanism.

For requests, supported features, and client configuration, follow
the [API guide](./ai-api).

## A practical guide to using AI chat

A useful prompt usually contains four elements:

1. **Task:** what you want the model to do.
2. **Context:** the material and background needed for the task.
3. **Constraints:** what to preserve, exclude, or treat as uncertain.
4. **Output:** the required format and level of detail.

For example:

> Using only the supplied methods section, extract the sample size,
> instruments, experimental conditions, and statistical tests.
> Return a table with one row per item and a supporting quotation.
> Write “not stated” when the section does not provide the information.

Review the response before refining the prompt. If something is
missing or incorrect, identify it directly and explain the correction
you need.

Clear instructions can improve usefulness, but they do not guarantee
accuracy. Verify references, calculations, extracted values, and
scientific claims against appropriate sources.

## Shared resources and benchmarking

The platform is shared across the research community. Response times
vary with model choice, request length, and current demand.

For automated work, limit concurrent requests and evaluate your
workflow on a small sample before processing a large dataset.

<Callout type="warning">
Independent benchmarks require prior consultation.
Contact [k8s@cerit-sc.cz](mailto:k8s@cerit-sc.cz) before running them.
</Callout>

Measurements on a shared service include queueing and other
operational effects. Record workload conditions when interpreting
performance results.

Effective June 30, 2026

We provide two kinds of models:

1. **Generative models** – the chat / multimodal / reasoning models you talk to, listed below.
2. **Embedding models** – instead of "talking," these convert text into numerical vectors. They power Semantic Search, Recommendation Engines, and Retrieval-Augmented Generation (RAG), letting your applications reason over the meaning and context behind your data.

We no longer split models into "guaranteed" and "experimental" tiers. Because our GPU capacity is limited and shared, **any model can be upgraded or replaced at any time** once a newer, better-performing version becomes available. The one part of the offering that stays stable over the long term is the set of maintained **[aliases](#model-aliases)** — short names such as `kimi` or `deepseek` that always keep pointing to a current model.

<Callout type="warn">
**No specific model version is guaranteed to stay available.** Because we run on limited, shared GPU hardware, we replace models with better ones as soon as they are available — usually at night, but possibly at any time — and retire the old **exact** model name. The hardware may also occasionally need maintenance (we have no backup of comparable scale) or be temporarily diverted to urgent high-priority tasks, during which availability can be suspended. We announce such changes on this page and via WebUI banners.
</Callout>

<Callout type="warn">
**For reproducible work (e.g. a bachelor's or master's / diploma thesis):** plan for a replacement happening right before a deadline or defense.
We do not guarantee that a specific model will remain available throughout the semester. 
- Call models through a maintained **[alias](#model-aliases)** so your code keeps running even after the underlying model is upgraded.
- An alias keeps your *code* working, not your *outputs* — a newer model may answer differently, so do not assume results stay reproducible over time.
- Keep local copies of important results, and if exact reproducibility is critical, contact us at **[k8s@cerit-sc.cz](mailto:k8s@cerit-sc.cz)** to discuss options.
</Callout>

<Callout type="info">
For exact, currently served model names, query the live model list via the API (see [Creating an API Key](#creating-an-api-key)) or check the [status page](https://llm.ai.e-infra.cz/status/). When accessing externally you must use either a maintained alias or the exact model name, e.g. `qwen3.8-27b` or `deepseek-v4.1-flash`.

#### Model Aliases

Because exact model versions change often, we maintain a set of short, version-independent **aliases**. These alias names are the part of our offering that stays stable over the long term: an alias always resolves to the *current* recommended model in its family, so code that calls an alias keeps working across upgrades without any changes on your side.

| Alias | Currently resolves to | Notes |
|-------|-----------------------|-------|
| `glm` | `glm-5.3` | latest GLM |
| `glm-5` | `glm-5.3` | legacy alias |
| `kimi` | `kimi-k3` | latest Kimi |
| `deepseek` | `deepseek-v4.1-flash` | reasoning **off** by default (can be enabled explicitly) |
| `deepseek-thinking` | `deepseek-v4.1-flash-thinking` | reasoning **on** |
| `thinker` | `deepseek-v4.1-flash-thinking` | |
| `mini` | `gpt-oss-120b` | |
| `coder`, `agentic` | `qwen3.8-flash-next` | |

`deepseek` and `deepseek-thinking` point to the same underlying weights; they differ only in whether step-by-step reasoning is enabled by default.

<Callout type="info">
**Which model name should I use?**

* **Use an alias** (e.g., `kimi`, `deepseek`) for **long-term stability**. Aliases always point to the latest recommended model version, ensuring your scripts don't break over time. 
  * *Trade-off:* Outputs may shift slightly as underlying models are upgraded.
* **Use an exact name** (e.g., `kimi-k3`) for **version consistency**. Recommended only when you need a specific, fixed model version. 
  * *Trade-off:* Exact names are short-lived and will be retired when replaced, which will cause scripts using them to fail until updated.

**Note on legacy aliases:** The `glm-5` alias still resolves to its updated equivalent for backward compatibility, but will be deprecated soon. Please update your code to `glm`.
</Callout>

## How Models are Added, Upgraded, and Removed

**Added.** New models are integrated after evaluation against industry-standard benchmarks, community feedback, and the latest open-source releases.

**Upgraded and removed.** Our GPU capacity is limited and shared, so we keep only the best-performing model in each family running on it. As soon as a newer model clearly outperforms one we host, we replace it — usually at night, but possibly at any time — and retire the old **exact** model name. We do not keep older versions around: large, resource-intensive models are removed promptly when their performance-to-cost ratio falls behind, so those GPUs can serve more capable models for the whole community.

**Long-term stability.** The stable part of the offering is the set of maintained **[aliases](#model-aliases)**, not any individual model version. An alias name stays valid across upgrades and always points to a current model, so workflows that call an alias keep running. If you need to reproduce results from a specific model version over a long period, save those results locally and contact us at **[k8s@cerit-sc.cz](mailto:k8s@cerit-sc.cz)** — we cannot guarantee that any exact version remains available.

## Knowledge Function (Alpha)

Open WebUI includes an experimental *Knowledge Function*, which is essentially a [RAG (Retrieval-Augmented Generation)](https://en.wikipedia.org/wiki/Retrieval-augmented_generation) system. This allows users to upload custom texts and query a model that generates answers based on that content.

Currently, the Knowledge Function only supports global configuration, meaning a single embedding model is used for all stored texts. We are still evaluating which embedding models are best suited for this purpose. A key limitation is that changing the embedding model requires all previously uploaded texts to be reprocessed, as RAG relies on consistent embeddings to function correctly. For this reason, the feature is not recommended for production use and is intended primarily for testing and preview.

Another challenge lies in finding suitable embedding models that support the Czech language and large input contexts. Most available models are limited to a 512-token input, which is suboptimal for longer texts, as it requires splitting the content into small fragments—often too small to provide high-quality answers.

While we could integrate external embedding models like OpenAI's `text-embedding-3-small`, this approach would compromise data privacy, as it involves sending data to a third-party service.



## A Practical Guide to Using AI Chat

As a scientist, you're likely no stranger to seeking out information and guidance to help you with your work. When interacting with AI chatbots, effective communication is key to getting the results you need. In this guide, we'll walk you through the best practices for crafting high-quality prompts and engaging in productive conversations with AI chatbots.

### Why Proper Prompting Matters
A poorly written prompt can lead to a subpar response. AI chatbots are only as good as the input they receive. By providing clear and concise prompts, you can unlock more accurate and relevant results.

### Communicating Effectively with AI
Interacting with chatbots is similar to communicating with humans. The quality of the response depends on the clarity and specificity of your prompt. Don't worry about complexity—focus on describing your task and asking questions.

### Basic Principles of Communication
1.	**Define Your Goal**: Clearly state what you want to achieve. The more specific you are, the better the response will be. Avoid vague or general prompts, as they can lead to disappointing results.
2.	**Provide Context**: Offer relevant details that can help the AI understand the task and provide a more accurate response. Context helps the AI grasp the purpose and significance of the task.
3.	**Specify the Output**: Indicate how you want the response to be formatted, including length, style, and tone. This ensures you receive a response that meets your needs.
4.	**Choose an appropriate language model**: Try different LLM models and compare the results.

### Let AI Help You Craft Prompts
1.	**Start with a Basic Idea**: Instead of struggling to come up with a prompt, ask the AI chatbot to help you create one. For example: "Create a high-quality prompt for a chatbot that will help me write engaging articles on productivity topics for my colleagues."
2.	**Specify the Purpose**: Add context about how you plan to use the prompt, such as: "I'll use this prompt to write articles on productivity topics for my colleagues."
3.	**Refine the Result**: The AI will provide a complete prompt that you can use as-is or refine to better suit your needs.

### Engaging in Productive Conversations with AI
1.	**Start with a Strong Prompt**: Begin with the best prompt you can craft, using the techniques outlined above.
2.	**Evaluate the Response**: Review the response and identify areas for improvement. AI chatbots may not always provide exactly what you want on the first try.
3.	**Refine Your Request**: Continue the conversation by providing specific feedback, such as: "Make it more concise" or "Write it in a more formal tone."
4.	**Repeat the Process**: Iterate until you achieve the desired result. Ask questions, provide feedback, and refine your prompt to get the best possible response.

### Improving Prompts with Roles and Details
1.	**Assign a Role to AI**: Provide context by assigning a role to the AI, such as: "Act as an expert copywriter with 15 years of experience." This helps the AI provide more relevant and sophisticated responses.
2.	**Describe the Problem in Detail**: Clearly explain the problem or task you want the AI to help with. Provide as much context as possible to ensure the AI understands your needs.
3.	**Specify the Output Format**: Indicate how you want the response to be formatted, such as a list, table, or paragraph.
4.	**Define the Tone and Style**: Specify the tone and style you want the AI to use, such as: "Write it in a friendly, approachable tone" or "Use a formal, technical tone."

### Using Examples for Better Results
1.	**Provide a Sample**: Offer a sample or example of what you're looking for. This helps the AI understand your needs and provide a more accurate response.
2.	**Use Positive Instructions**: Instead of telling the AI what not to do, focus on what you want it to do. For example: "Use simple language" instead of "Avoid technical jargon."
3.	**Avoid Conflicting Instructions**: Be consistent in your prompts and avoid contradictory instructions.
4.	**Let AI Ask Questions**: Encourage the AI to ask questions if it needs clarification or more information. This can help ensure you receive a more accurate and relevant response.
