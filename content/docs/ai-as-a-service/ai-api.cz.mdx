## Úvod do API

Tato dokumentace obsahuje podrobný návod pro vytváření a používání **API klíčů** pro přístup k lokálně běžícím velkým jazykovým modelům (LLM) na infrastruktuře e-INFRA CZ, konkrétně prostřednictvím rozhraní Open WebUI [https://chat.ai.e-infra.cz](https://chat.ai.e-infra.cz). Návod je určen výzkumníkům a vědcům, kteří chtějí tyto modely integrovat do svých aplikací, skriptů nebo AI workflow přes API.


Pro přístup ke službě Open WebUI a vytvoření API klíče musíte splnit následující předpoklady:

* Platný účet MetaCentrum (pro české výzkumné instituce)
* Nebo aktivní účet Masarykovy univerzity (pokud jste k ní přidruženi).

Komplexní popis dostupných modelů najdete v [dokumentaci Chat AI](../ai-as-a-service/chat-ai).

## Vytvoření API klíče

<Callout type="warn">
API klíč nesdílejte s jinými osobami. Sdílení API klíčů představuje významné bezpečnostní riziko a je v přímém rozporu s podmínkami používání. Pokud bude zjištěno neoprávněné sdílení nebo zneužití, může být příslušný přístup k API okamžitě zablokován.
</Callout>


API klíče slouží jako autentizační tokeny pro zabezpečený přístup k API endpointu Open WebUI. Postupujte podle těchto kroků pro vytvoření a použití API klíče:

**Postup krok za krokem**

1. Přejděte do sekce Nastavení v rozhraní Open WebUI [https://chat.ai.e-infra.cz](https://chat.ai.e-infra.cz).
2. Otevřete Account (Účet).
3. Klikněte na API keys (zobrazit).
4. Ignorujte JWT token, vyberte API key, a buď vygenerujte nový, nebo zobrazte stávající.
5. Zkopírujte vygenerovaný API klíč a bezpečně jej uložte.
6. Tento klíč používáte v API požadavcích k autentizaci a přístupu ke službám Open WebUI.
7. Základní endpoint pro Open-WebUI API je: `https://llm.ai.e-infra.cz/v1/`. Tento endpoint se řídí specifikací OpenAI API, což umožňuje kompatibilitu s mnoha existujícími LLM frameworky a aplikacemi.

## Používání API klíče

Podrobné specifikace API naleznete v [referenční dokumentaci API](https://developers.openai.com/api/reference/overview). Upozorňujeme, že ne všechny endpointy jsou podporovány.

Pro přístup klientů a vývoj doporučujeme použít [LiteLLM SDK](https://docs.litellm.ai/docs/#litellm-python-sdk) nebo [OpenAI Client Libraries](https://developers.openai.com/api/docs/libraries/), které poskytují dobře udržované, produkčně připravené integrace.

<Callout type="info"> 
Uživatel může sledovat spotřebu LLM tokenů přímo prostřednictvím nového osobního dashboardu na [llm.ai.e-infra.cz/usage](https://llm.ai.e-infra.cz/usage).
- Dostupný po přihlášení vaším `e-INFRA CZ účtem`.
- Dashboard monitoruje tokeny spotřebované výhradně přes **API endpoint**. 

Poznámka: Tokeny vygenerované přes WebUI zde nejsou sledovány.
</Callout>


### Výpis dostupných modelů

[Aktuálně dostupné modely](/docs/ai-as-a-service/chat-ai#currently-available-models)

<Callout type="info">
Aktuální stav všech dostupných modelů je zobrazen na [https://llm.ai.e-infra.cz/status/](https://llm.ai.e-infra.cz/status/)
</Callout>

Před dotazováním modelu se ujistěte, že používáte správný název modelu. Pro získání seznamu všech dostupných modelů na infrastruktuře e-INFRA CZ spusťte následující příkaz pomocí nástrojů `curl` a `jq`.
Nahraďte `${E_INFRA_API_TOKEN}` svým skutečným tokenem.

```shell
curl -H "Authorization: Bearer ${E_IN...KEN}" https://llm.ai.e-infra.cz/v1/models | jq .data[].id
```

Očekávaný výstup (příklad):

```
"llama3.3:latest"
"llama3.3:70b-instruct-fp16"
"deepseek-r1:32b-qwen-distill-fp16"
"qwen2.5-coder:32b-instruct-q8_0"
"aya-expanse:latest"
```

Tento seznam odráží identifikátory modelů (`id`), které lze dotazovat přes API. Identifikátory se řídí pojmenovávací konvencí, která obvykle zahrnuje:

* Název modelu (např. `llama3.3`, `qwen2.5-coder`).
* Tag kvantizace (např. `fp16`, `q8_0`), který indikuje, jak je model optimalizován pro inference (důležité pro výkon a spotřebu zdrojů).
* Variantu nebo revizi (např. `:latest`, `:70b-instruct-fp16`).


### Příklad API požadavku

Níže je uveden příklad, jak použít API klíč k dotazu na model LLaMA 3.3 (`llama3.3:latest`) pomocí požadavku chat completions:

```bash
curl https://llm.ai.e-infra.cz/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${E_IN...KEN}" \
  -d '{
    "model": "mini",
    "messages": [
      {
        "role": "user",
        "content": "Explain the impact of machine learning on climate research in 100 words or less."
      }
    ]
  }'
```

Očekávaný výstup (příklad):

```json
{
  "id": "chatcmpl-XYZ123",
  "object": "chat.completion",
  "model": "mini",
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "Machine learning (ML) is revolutionizing climate research by unlocking unprecedented insights..."
      },
      "index": 0,
      "finish_reason": "length"
    }
  ]
}
```

## Integrace s frameworky

e-INFRA CZ LLM API je navrženo tak, aby bylo kompatibilní se specifikací OpenAI API, což znamená, že jej lze integrovat do frameworků původně vytvořených pro služby OpenAI.

### Doporučený přístup pro MCP servery

Pro požadavky odesílané z MCP serveru doporučujeme nastavit příznak `"stream": true`, aby brána (gateway) průběžně odesílala SSE části odpovědi během generování modelu a tím udržovala spojení aktivní. MCP server může jednotlivé části připojovat do bufferu a po skončení streamu vrátit svému klientovi jednu kompletní odpověď.

<Callout type="warning" title="Doporučujeme streamovat požadavky z MCP serverů">
Pokud tento přístup není dodržen, může požadavek skončit chybou HTTP `408` bez ohledu na timeout nakonfigurovaný v MCP klientovi nebo serveru. Timeout infrastruktury e-INFRA pro nestreamované volání je 30 minut a nelze jej přepsat nastavením aplikace.
</Callout>

Doporučená posloupnost:

1. MCP server odešle požadavek chat completions s příznakem `"stream": true`.
2. Během generování modelu brána průběžně odesílá malé SSE části odpovědi, např. `…the`, ` filter` a ` protects…`.
3. MCP server každou část okamžitě přečte a připojí ji do bufferu. Průběžný tok dat udržuje spojení aktivní.
4. Když stream skončí, server sestaví stejný kompletní objekt jako u nestreamovaného volání — text odpovědi, model, `stop_reason`, `usage` a případný `thinking` obsah.
5. Sestavený objekt vrátí MCP klientovi jednou.

MCP server tedy zpracovává SSE stream průběžně na svém spojení k e-INFRA CZ LLM API, přičemž zachovává své stávající rozhraní vůči klientům a vrací pouze finální kompletní objekt.

**Příklad integrace PyDanticAI**

PyDanticAI je framework, který zjednodušuje interakce s LLM pomocí OpenAI-kompatibilních modelů. Použijte následující konfiguraci pro autentizaci vůči e-INFRA CZ LLM endpointu:

Příklad konfigurace `PydanticAI` pro integraci s naším API (podobné nastavení použijte i pro jiné frameworky):

```python
from pydantic_ai_provider import OpenAIModel, OpenAIProvider
import os

model = OpenAIModel(
    'deepseek',
    provider=OpenAIProvider(
        base_url="https://llm.ai.e-infra.cz/v1",
        api_key=os.getenv("E_INFRA_API_TOKEN"),
    ),
)
```

Kromě PyDanticAI lze podobné konfigurace použít pro:

* LangChain
* LlamaIndex
* Aplikace postavené na FastAPI
* Jakékoli jiné frameworky nebo klienty, které podporují vlastní endpointy OpenAI API.

## Reasoning modely v API

Některé modely jsou **hybridní** a podporují jak režim *reasoning (přemýšlení)*, tak režim *bez reasoning*.

V chatovacím UI je většina hybridních modelů přednastavena na reasoning režim, což znamená, že můžete vidět mezikrok `thinking` před vrácením finální odpovědi. V API však výchozí chování závisí na konkrétním modelu.

### DeepSeek

Ve výchozím nastavení běží **DeepSeek** *bez* zapnutého reasoning. Pro jeho zapnutí předejte dodatečné parametry přes `chat_template_kwargs`:

```bash
curl https://llm.ai.e-infra.cz/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ***" \
  -d '{
    "model": "deepseek",
    "messages": [
      {
        "role": "user",
        "content": "What are 5 creative things I could do with my kids'' art? I don''t want to throw them away, but it''s also so much clutter."
      }
    ],
    "chat_template_kwargs": {
      "thinking": true
    }
  }'
```

Pro pohodlí — a pro prostředí, kde nelze `chat_template_kwargs` použít (například někteří AI agenti) — poskytujeme také dedikovanou reasoning variantu s názvem **`deepseek-thinking`**, která je trvale donucena do thinking režimu.

Tyto možnosti můžete použít k řízení toho, zda je mezikrokové reasoning zahrnuto v API odpovědích, podle potřeb vaší aplikace.

## Získávání metadat modelů přes API

Metadata o všech dostupných modelech můžete získat prostřednictvím endpointu /model/info. Ten zahrnuje údaje jako název modelu, schopnosti, velikost kontextu, zdroj a kvantizaci.

**Příklad požadavku**

```bash
curl --location 'https://llm.ai.e-infra.cz/v1/model/info' --header 'Content-Type: application/json' --header 'Accept: application/json, text/event-stream' --header 'x-litellm-api-key: *** TOKEN'  | jq '[.data[] | {model_name, capabilities: .model_info.capabilities, context_size: .model_info.context_size, model_source: .model_info.model_source, quantization: .model_info.quantization}]'
```

**Příklad odpovědi**

Odpověď je JSON pole obsahující metadata pro každý model.
